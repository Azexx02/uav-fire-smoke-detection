# 林焰智巡模型训练与误报治理答辩稿

## 一、答辩开场

各位评委老师好，下面我重点介绍本项目中模型训练和误报治理的过程。我们不是只训练了一版模型后直接用于展示，而是按照“发现问题 - 整理样本 - 明确标注规则 - 微调训练 - 回归测试 - 版本取舍”的流程持续迭代。

这个过程的核心目标有两个：第一，保证模型能够识别火焰和烟雾；第二，尽量减少非火灾场景下的误报。对于火灾检测系统来说，误报和漏报都需要控制。漏报会影响安全性，误报会影响系统可信度。如果系统经常把灯光、反光、红色物体、屏幕内容或者打印图片误判为火灾，实际使用时就很难让人信任。

## 二、训练任务和类别定义

本项目使用 YOLOv8 目标检测框架，检测类别为两类：

| 类别 ID | 类别名称 | 含义 |
| --- | --- | --- |
| 0 | fire | 火焰 |
| 1 | smoke | 烟雾 |

在标注阶段，我们统一约定：只有真实需要模型识别的火焰或烟雾区域才标框；无火、无烟或者误报抑制样本不标任何框，标签文件保持为空。这样做的目的是让模型明确学习到：这些图像虽然可能有亮光、红色区域、反光或复杂背景，但不应该被判定为 fire 或 smoke。

这一点对误报治理非常重要。如果负样本中错误保留了检测框，模型会把错误特征继续当成正样本学习，后续误报反而更难降低。因此在训练前，我们先检查了新增样本的标注规则，确认火焰为 0，烟雾为 1，负样本为空标签。

## 三、初始问题：为什么会出现误报

最初模型具备基础火焰和烟雾识别能力，但在实际测试中会出现一些误报。主要原因有三类：

1. 视觉特征相似。火焰和烟雾本身没有固定形状，火焰颜色与灯光、反光、红色物体相似，烟雾纹理与阴影、雾气、模糊背景相似。
2. 训练数据覆盖不足。公开数据集能够提供基础识别能力，但不一定覆盖我们现场摄像头、室内光照、打印展示、手机屏幕、桌面背景等具体场景。
3. 正负样本边界不清。模型如果只看到大量火焰和烟雾正样本，却很少看到“像火但不是火”“像烟但不是烟”的样本，就容易在相似场景中误判。

因此，误报问题不能只靠调高置信度阈值解决。调高阈值虽然可以减少一部分误报，但也可能带来漏检。更合理的方式是补充困难负样本，让模型真正学会区分相似但不属于火灾的画面。

## 四、误报治理思路

我们采用的是困难负样本挖掘，也就是 hard negative mining。

具体做法是：先使用当前模型在真实摄像头画面、历史记录和误报样本中进行检测；然后把被模型误判为 fire 或 smoke 的图片整理出来；接着确认这些图片中实际没有火焰或烟雾目标；最后将它们作为空标签负样本加入训练集继续微调。

这个流程的意义是让模型直接面对自己最容易出错的样本。相比随机添加普通背景图，困难负样本更能针对性降低误报。

我们的误报治理过程可以概括为：

1. 收集模型误报图片。
2. 人工确认图片中是否真的存在 fire 或 smoke。
3. 对无火无烟样本清空标签，作为负样本。
4. 对确实存在火焰或烟雾的样本按类别重新标注。
5. 在上一版模型基础上继续微调。
6. 用旧误报样本池进行回归测试，确认误报是否下降。

## 五、版本迭代过程

项目中模型不是一次完成，而是经历了多个阶段。

第一阶段是基础检测模型。这个阶段主要建立 fire 和 smoke 的基础识别能力，保证模型能够在常规火灾烟雾数据上完成检测。

第二阶段是误报抑制模型，也就是偏真实场景使用的版本。我们加入了近期收集的误报负样本，让模型减少对打印照片、手机屏幕、灯光反射、普通无火无烟画面的误判。这个阶段的模型更接近真实部署逻辑：系统应该识别真实场景中的火焰和烟雾，而不是把二次成像内容轻易当成火灾。

第三阶段是展示适配模型，也就是当前的 v4.0_for_preview。因为比赛现场不能真正点火，评委要求必须通过摄像头识别展示，因此我们需要准备一版适用于现场演示的模型。这个版本在保留火焰、烟雾识别能力的基础上，加入了新的强化样本和困难负样本，使它更适合摄像头实时展示。

这里需要说明的是，不同版本不是简单地“新版本一定替代旧版本”，而是根据目标场景选择。真实部署更强调保守、低误报；现场展示更强调可演示、可识别。我们在训练中明确区分了这两类目标。

## 六、训练中的关键技术点

### 1. 空标签负样本

空标签负样本是误报治理的关键。对于无火无烟图片，我们不标任何框，而不是给它标一个“非火灾”类别。YOLO 检测任务中，空标签图片会告诉模型：这张图中没有需要检测的目标。这样模型就能学习背景、反光、灯光、屏幕等干扰特征不应该被输出为 fire 或 smoke。

### 2. 困难样本优先

普通背景图对降低误报有帮助，但效果有限。真正有效的是模型已经误报过的样本，因为这些样本正好位于模型分类边界附近。把这些样本加入训练，相当于把模型最薄弱的位置重新训练一遍。

### 3. 小步微调

我们没有直接从头训练，而是在已有较好模型的基础上继续微调。这样可以保留原有火焰、烟雾识别能力，同时让模型针对新问题进行修正。从工程上看，小步微调风险更低，也更容易比较每次数据加入后的变化。

### 4. 回归测试

每次模型更新后，不能只看训练指标，还要回到旧误报样本池上测试。如果新模型在旧误报样本上仍然大量误报，说明问题没有真正解决；如果旧误报明显下降，同时正样本识别仍保持稳定，才说明训练方向是有效的。

## 七、当前模型性能结果

当前 v4.0_for_preview 的最终验证指标如下：

| 指标 | 数值 |
| --- | ---: |
| Precision | 0.88217 |
| Recall | 0.86460 |
| mAP50 | 0.91846 |
| mAP50-95 | 0.66894 |

其中，mAP50 达到 0.91846，说明模型在常规目标检测评价条件下具有较高检测精度。Precision 为 0.88217，说明误报控制表现较好。Recall 为 0.86460，说明目标检出能力较稳定。mAP50-95 为 0.66894，说明在更严格的边界框定位评价下仍有继续优化空间。

补充回归测试中，旧误报样本池 322 张中仍有 2 张误报，误报率约为 0.62%。综合负样本回归测试 338 张中仍有 2 张误报，误报率约为 0.59%。这说明模型对已收集误报样本的抑制效果较明显，但并不是说误报已经完全消失，后续仍需要继续收集新场景中的困难负样本。

## 八、如果评委问“为什么不只是调阈值”

可以这样回答：

调高置信度阈值确实可以减少一部分误报，但它不是根本解决方案。因为阈值调高后，低置信度的真实火焰或烟雾也可能被过滤掉，带来漏检风险。我们的做法是先通过数据解决问题，也就是把误报样本作为困难负样本加入训练，让模型学会区分相似干扰物。阈值调整只是部署阶段的辅助策略，不应该替代数据和训练本身。

## 九、如果评委问“怎么证明误报真的下降”

可以这样回答：

我们不是只看训练集指标，而是保留了历史误报样本池做回归测试。每次模型更新后，都用这些曾经误报过的样本重新测试。当前版本在旧误报样本池 322 张中只有 2 张仍然误报，误报率约为 0.62%。这说明模型不是只在验证集上表现好，而是对之前实际暴露出来的问题有针对性改善。

## 十、如果评委问“你们怎么处理标注质量”

可以这样回答：

我们对标注规则做了统一约定：fire 类为 0，smoke 类为 1；确实存在火焰或烟雾的样本才标框；无火无烟的负样本保持空标签。训练前会检查标签文件，尤其是负样本是否误带检测框。因为负样本一旦错误标框，模型就会继续学习错误特征，这会直接影响误报治理效果。

## 十一、如果评委问“当前模型还有什么不足”

可以这样回答：

当前模型的 mAP50 较高，说明常规检测效果较好，但 mAP50-95 相对低一些，说明在更严格的定位标准下，检测框精细程度还有提升空间。另外，误报治理依赖持续收集困难负样本，目前只能说明模型对已收集的误报样本抑制效果较好，不能保证所有未来场景都完全无误报。后续还需要继续补充夜间、强反光、烟雾稀薄、小火点和复杂背景样本。

## 十二、总结陈述

总体来说，我们的模型训练不是简单地调用一次训练命令，而是围绕真实测试中暴露的问题进行了多轮迭代。误报问题的解决思路是：先找到误报来源，再整理负样本和困难样本，统一标注规则，在上一版模型基础上继续微调，最后用历史误报样本池做回归验证。

这个过程体现了一个完整的模型工程闭环：数据驱动问题发现，标注规则保证训练质量，困难负样本提升模型边界判断能力，回归测试验证迭代是否有效。当前 v4.0_for_preview 在保持火焰、烟雾识别能力的同时，对已收集误报样本有较好的抑制效果，也为后续继续优化提供了明确方向。

## 十三、如何解决模型过拟合

如果评委问模型是否存在过拟合，可以从“现象、原因、处理方法”三个层面回答。

过拟合的典型表现是：训练集指标继续变好，但验证集指标不再提升，甚至出现下降；或者模型在训练样本上检测很好，但换到新的摄像头画面、不同光照和不同背景后误报或漏检明显增加。

本项目中控制过拟合主要采用以下方法：

1. 保留独立验证集。训练时不只看训练损失，也观察 Precision、Recall、mAP50、mAP50-95 等验证指标。如果训练损失下降但验证指标没有提升，就不能继续盲目增加轮数。
2. 使用数据增强。通过尺度变化、平移、颜色扰动、翻转等增强方式，让模型看到更多形态变化，减少对固定背景、固定角度和固定亮度的依赖。
3. 加入负样本和困难负样本。过拟合不只发生在正样本上，也会表现为模型记住某些“像火”的错误特征。通过加入误报样本作为空标签负样本，可以让模型学习更清晰的判别边界。
4. 小步微调而不是长时间重训。对于已经具备较好基础能力的模型，我们采用短轮次微调，避免新数据量较小时模型过度贴合新增样本。
5. 用回归测试检查泛化。训练后不仅看当前验证集，还用历史误报样本池和新增负样本测试，确认模型没有只对某一批数据有效。

答辩时可以这样说：

我们没有把训练集指标作为唯一判断依据，而是同时观察验证集指标和历史误报样本回归测试。对于小规模新增样本，我们采用继续微调和困难负样本补充，而不是长时间从头训练，这样可以降低过拟合风险。模型训练后还会回到旧误报样本池测试，确认它不是只记住了新增样本，而是真正提升了干扰场景下的判别能力。

## 十四、如何解决模型性能下降

模型性能下降通常有几种原因：新增样本质量不稳定、标注不一致、负样本比例过高、训练轮数过多、学习率不合适，或者新数据分布与原始数据差异过大。

我们的处理思路是先定位原因，再决定是否回退或继续训练。

1. 检查标注是否正确。首先确认 fire 是否仍为 0，smoke 是否仍为 1，负样本是否为空标签。如果标签映射错误，模型性能会明显下降。
2. 对比 Precision 和 Recall。如果 Precision 下降，通常说明误报变多；如果 Recall 下降，通常说明漏检变多。两者下降的处理方法不同。
3. 检查新增数据比例。如果短时间加入大量负样本，模型可能变得过于保守，导致真实火焰或烟雾检不出来。此时需要补充正样本，或者降低负样本权重。
4. 保留上一版稳定模型。每次训练完成后保存 best.pt，并保留上一版效果较好的模型。如果新模型性能下降，可以回退到上一版，再调整数据或训练参数。
5. 使用小轮次验证。先用少量 epoch 做试训，观察指标方向是否正确，再决定是否继续完整训练。

答辩时可以这样说：

我们处理性能下降不是直接继续堆数据，而是先判断下降发生在哪个指标上。如果 Precision 下降，说明误报增加，需要补充负样本或检查干扰样本；如果 Recall 下降，说明模型过于保守，需要补充正样本或调整阈值。每一版模型都会保留权重和测试结果，因此出现性能下降时可以回退到上一稳定版本，再重新调整训练数据。

## 十五、如何提高训练效率

训练效率不只是让训练速度更快，也包括减少无效训练次数。项目中的效率优化主要体现在以下几个方面：

1. 使用预训练模型。我们不是从零开始训练，而是在 YOLOv8 预训练权重或上一版项目模型上继续训练。这样可以利用已有的通用视觉特征，减少训练时间。
2. 采用增量微调。新增误报样本或强化样本后，不重新训练全部流程，而是在上一版模型基础上短轮次微调，提高迭代效率。
3. 先小规模试训。对于新数据，先跑少量 epoch 看指标方向。如果指标明显变差，就先检查数据和标签，而不是浪费时间完整训练。
4. 固定输入尺寸。统一使用 640 尺度训练和评估，减少不同尺度切换带来的额外成本，也便于后续部署到板端。
5. 分阶段处理数据。先解决最明显的误报，再解决展示样本识别问题，避免把所有问题混在同一轮训练里导致无法判断数据贡献。
6. 使用 GPU/CUDA 训练。训练阶段调用 CUDA 加速，推理部署阶段再转换为适合 RK3588 的 RKNN 格式，两者目标不同。

答辩时可以这样说：

我们的训练效率主要来自两个方面：一是使用预训练模型和上一版权重继续微调，避免从零开始；二是先进行小轮次试训，通过验证指标判断数据方向是否正确。这样每次新增样本后都能快速判断模型是变好还是变差，减少无效训练时间。

## 十六、如何微调模型

微调不是简单地把新数据加入后重新训练，而是要明确“为什么微调”和“希望模型改变什么”。

本项目中的微调流程如下：

1. 明确微调目标。例如降低误报、提升展示样本检出、改善烟雾漏检等。
2. 整理对应数据。如果目标是降低误报，就加入困难负样本；如果目标是提高检出，就补充正样本并保证标注准确。
3. 从稳定版本开始。选择上一版综合效果较好的 best.pt 作为起点，而不是从头训练。
4. 控制训练轮数。新增数据量不大时，采用较少 epoch 微调，避免模型过度贴合新增样本。
5. 对比训练前后指标。重点对比 Precision、Recall、mAP50、mAP50-95，以及误报样本池回归结果。
6. 选择是否保留新版本。如果新模型解决了目标问题且没有明显牺牲其他指标，就保存为新版本；否则回退并调整数据。

答辩时可以这样说：

我们每次微调前都会先定义目标。例如某一轮的目标是降低误报，那么训练数据重点加入空标签负样本；如果目标是提升某类场景检出，则补充对应正样本。微调完成后，不只看总 mAP，还会看误报样本池和正样本检出情况，确保模型确实解决了本轮目标问题。

## 十七、少样本情况下如何提升模型性能

少样本场景下，最重要的是提高样本质量，而不是单纯追求数量。少量高价值样本往往比大量普通背景图更有效。

本项目采用的少样本提升方法包括：

1. 使用预训练权重。预训练模型已经学习了边缘、纹理、颜色和常见目标特征，少量火焰烟雾数据只需要在此基础上调整判别边界。
2. 优先收集困难样本。少样本时应优先收集模型最容易出错的样本，例如灯光反射、红色物体、屏幕内容、复杂背景、弱烟雾和小火点。
3. 做好标注质量控制。少样本中每一张图的影响都更大，标签错误会被模型放大，因此必须保证 fire、smoke 和空标签规则正确。
4. 数据增强。通过亮度、尺度、平移、翻转等增强方式扩展样本变化，提高模型对不同拍摄条件的适应能力。
5. 使用回归测试。少样本训练容易看起来指标变好，但实际泛化不一定提升，因此需要用固定测试集和历史误报样本池检验效果。
6. 分阶段加入数据。不要一次性混入所有新增样本，而是按问题分批加入，观察每批样本对模型的影响。

答辩时可以这样说：

少样本情况下，我们更关注样本的针对性和标注质量。比如误报治理中，最有价值的不是普通无火图片，而是模型已经误报过的困难负样本。通过预训练模型、小步微调、数据增强和回归测试，即使新增样本数量不大，也能让模型在关键错误场景上得到明显改善。

## 十八、训练答辩中的整体逻辑

如果需要把上述问题串成一段完整回答，可以这样组织：

我们训练模型时不是只追求单次 mAP，而是把模型训练看作一个持续迭代过程。首先用基础数据建立 fire 和 smoke 的识别能力；然后在实际摄像头测试中收集误报和漏报；接着按照统一标注规则整理正样本、负样本和困难负样本；再在上一版稳定模型基础上进行小步微调；最后用验证集和历史误报样本池做回归测试。对于过拟合，我们通过验证集、数据增强、短轮次微调和回归测试控制；对于性能下降，我们分析是 Precision 下降还是 Recall 下降，再决定补充负样本、正样本或回退版本；对于少样本问题，我们优先使用高价值困难样本，而不是盲目增加普通样本。这样整个训练过程是可解释、可回退、可验证的。

## 十九、如何防止新数据造成灾难性遗忘

灾难性遗忘指的是模型在学习新数据、新场景或新问题时，原来已经学会的能力被破坏。例如，为了降低误报加入大量负样本后，模型可能变得过于保守，导致原本能识别的真实火焰或烟雾检不出来；或者为了适配某一类展示样本，模型对原始真实场景的泛化能力下降。

本项目中防止灾难性遗忘主要采用以下思路：

1. 不只使用新数据训练。微调时不能只喂新增样本，而要保留一部分原始火焰、烟雾正样本和代表性旧样本。这样模型在学习新问题的同时，不会忘记原有识别能力。
2. 保留固定验证集和回归测试集。每次训练后都用同一批验证样本、历史误报样本池和关键正样本做测试。如果新模型解决了新问题，但旧场景性能明显下降，就不能直接替换。
3. 控制负样本比例。如果新增负样本过多，模型会倾向于“不报”，Precision 可能提高，但 Recall 会下降。因此负样本需要和正样本保持合理比例，避免模型只学会抑制告警。
4. 小步微调。新增数据量较小时，不进行长时间训练，而是在上一版稳定模型上短轮次微调，降低模型参数被新数据大幅拉偏的风险。
5. 保留上一版稳定权重。每一轮训练都保留上一版 best.pt。如果新模型出现灾难性遗忘，可以回退到旧版本，再调整数据比例或训练轮数。
6. 对比关键指标。重点观察 Precision、Recall、mAP50、mAP50-95 的变化。如果 Precision 上升但 Recall 明显下降，说明模型可能过度学习负样本；如果 Recall 保持但 Precision 下降，说明新数据可能引入了新的误报风险。
7. 分批加入新数据。不要一次性把大量新样本全部加入训练，而是按问题分批加入。例如先加入误报负样本，确认误报下降且 Recall 不明显下降后，再加入展示强化样本。

答辩时可以这样说：

为了防止灾难性遗忘，我们没有只用新增数据单独训练，而是在上一版稳定模型基础上做小步微调，并保留原有代表性样本参与训练。每次训练后，我们都会同时检查新问题是否解决，以及旧能力是否保留。具体来说，会比较 Precision、Recall、mAP50 和历史误报样本池结果。如果新模型虽然降低了误报，但 Recall 明显下降，说明它可能变得过于保守，这种版本不会直接采用。我们也保留每一版模型权重，必要时可以回退到上一稳定版本。

如果需要更简短地回答，可以说：

我们通过“旧样本混合训练、固定回归测试、小步微调、控制负样本比例、保留历史版本”来防止灾难性遗忘。新模型必须同时满足两个条件：一是解决新增数据暴露的问题，二是不能明显破坏旧数据上的检测能力。

## 二十、如何处理类别不均衡

类别不均衡指训练集中 fire、smoke 或背景样本数量差异较大，导致模型更偏向样本数量多的类别。比如 fire 样本明显多于 smoke 时，模型可能更容易学习火焰特征，而对烟雾边界、稀薄烟雾或小面积烟雾的识别不够稳定。

处理思路主要有四点：

1. 在数据层面补充弱势类别样本。对于 smoke 较少的情况，优先补充不同浓度、不同背景、不同光照下的烟雾样本。
2. 在增强层面扩大样本变化。通过亮度、尺度、裁剪、平移等增强方式增加样本形态多样性。
3. 在评估层面分别观察类别表现。不能只看总 mAP，还要结合混淆矩阵观察 fire 与 smoke 的识别情况。
4. 在误报治理时避免负样本过量。负样本过多会让模型更保守，可能进一步影响少数类召回。

答辩时可以这样说：

我们不会只看总体指标，而会结合标签分布图和混淆矩阵观察类别是否均衡。如果发现某类样本不足或召回偏低，会优先补充该类别的代表性样本，并通过数据增强扩大样本变化范围。

## 二十一、如何保证训练集和验证集没有数据泄漏

数据泄漏是指训练集和验证集出现高度重复或同源样本，导致验证指标虚高。比如同一段视频中相邻帧同时出现在训练集和验证集，模型可能只是记住了背景，而不是真正具备泛化能力。

处理方式包括：

1. 按来源划分数据，而不是完全随机划分。来自同一视频、同一批拍摄、同一组连续帧的样本尽量放在同一个集合中。
2. 对新增样本去重。相似图片、重复截图、连续帧要避免同时进入训练集和验证集。
3. 保留独立回归测试。历史误报样本池不参与训练评估混用，用于训练后独立检查。
4. 不只依赖验证集指标。结合现场摄像头测试和专家评审结果判断实际效果。

答辩时可以这样说：

我们会尽量按数据来源划分训练和验证样本，避免同一场景的连续帧同时出现在训练和验证中。同时保留历史误报样本池做独立回归测试，防止验证指标因为数据重复而虚高。

## 二十二、如何保证标注一致性

目标检测模型对标注质量非常敏感。标注不一致会直接影响模型学习，例如同样的烟雾有时标、有时不标，或者火焰边界框大小差异过大，都会导致模型判断边界混乱。

本项目的标注一致性原则是：

1. 类别固定：fire 为 0，smoke 为 1。
2. 有目标才标框，无火无烟样本保持空标签。
3. 标框覆盖主要可见区域，不刻意框入大量无关背景。
4. 对模糊边界样本保持统一尺度，避免同类目标标注标准前后不一致。
5. 训练前抽查标签文件，重点检查负样本是否误带框、类别 ID 是否错位。

答辩时可以这样说：

我们把标注质量作为训练前置步骤，而不是训练后的补救步骤。尤其是负样本必须保持空标签，否则模型会把误报特征继续学习进去。对于类别 ID，我们固定 fire 为 0、smoke 为 1，并在训练前检查标签文件。

## 二十三、如何选择置信度阈值

置信度阈值直接影响误报和漏检。阈值越高，模型越谨慎，误报可能下降，但漏检可能增加；阈值越低，召回可能提高，但误报风险也会上升。

选择阈值时主要参考：

1. Precision-Confidence 曲线。观察阈值升高时误报控制是否明显改善。
2. Recall-Confidence 曲线。观察阈值升高后真实目标是否大量丢失。
3. F1-Confidence 曲线。选择 Precision 和 Recall 综合较优的区间。
4. 实际场景需求。安全预警更关注漏检风险，但展示和巡检也必须控制误报。

答辩时可以这样说：

阈值不是随便设的，而是结合 Precision、Recall 和 F1 曲线选择。我们默认阈值为 0.25，同时保留前端调节能力，用于在不同光照和场景下平衡误报与漏检。

## 二十四、如何平衡误报和漏报

火灾检测中误报和漏报都重要，但风险不同。漏报可能导致真实火情没有被发现；误报过多会降低系统可信度，导致现场人员忽视告警。

本项目采用的平衡策略是：

1. 训练层面：加入困难负样本降低误报，同时保留正样本防止召回下降。
2. 指标层面：同时观察 Precision 和 Recall，不只优化单一指标。
3. 阈值层面：通过置信度阈值微调误报和漏报的平衡。
4. 系统层面：保留历史记录和专家评审，便于持续发现误报和漏报样本。

答辩时可以这样说：

我们没有单纯追求“尽量不报”或“尽量多报”，而是同时观察 Precision 和 Recall。如果误报多，就补充负样本；如果漏检多，就补充正样本并检查阈值。最终目标是在可接受误报水平下保持较稳定的目标检出能力。

## 二十五、为什么选择 YOLOv8

2. 工程部署方便。YOLOv8 可以导出 ONNX，再转换为适合边缘设备的 RKNN 格式。
3. 训练和微调流程成熟。对于新增样本、负样本和困难样本，可以较快完成迭代。

答辩时可以这样说：

我们选择 YOLOv8 是因为它更适合实时目标检测任务。相比只追求高精度的大模型，YOLOv8 在推理速度、训练效率和板端部署之间更平衡，更符合本项目的摄像头实时演示和边缘部署需求。

## 二十六、为什么不用更大的模型

更大的模型可能提升精度，但也会带来更高推理延迟、更大显存占用和更复杂的板端部署成本。本项目需要在 RK3588 开发板上运行，不能只考虑训练指标，还要考虑实时检测能力。

答辩时可以这样说：

更大模型可能在某些指标上更高，但我们的目标不是离线图片检测，而是摄像头实时识别。模型需要在边缘设备上稳定运行，因此我们选择轻量模型并通过数据迭代、困难负样本和微调提升实际效果，而不是单纯堆模型规模。

## 二十七、如何处理小目标检测问题

火焰和烟雾在早期可能面积很小，小目标检测是火灾识别中的难点。小目标容易被缩放、压缩、模糊和背景干扰影响。

处理方法包括：

1. 保留足够输入分辨率。默认使用 640 输入尺度，避免目标过度压缩。
2. 补充小火点、小烟雾样本。
3. 使用数据增强，让模型适应不同大小和位置的目标。
4. 结合检测框分布图分析目标尺寸，判断训练集中是否有足够小目标样本。

答辩时可以这样说：

我们通过标签分布图观察目标框尺寸，发现小尺寸目标占一定比例，因此训练中保留 640 输入尺度，并通过补充小目标样本和数据增强提高模型对早期火焰、烟雾的识别能力。

## 二十八、如何处理烟雾识别难的问题

烟雾比火焰更难识别，因为烟雾边界模糊、颜色不固定，容易和雾气、阴影、模糊背景混淆。

处理方式包括：

1. 补充不同浓度、不同背景下的烟雾样本。
2. 保持烟雾标注规则一致，不随意扩大或缩小标注框。
3. 加入类似烟雾但不是烟雾的负样本，例如阴影、白墙反光、模糊区域。
4. 通过混淆矩阵观察 smoke 是否被误判为 background 或 fire。

答辩时可以这样说：

烟雾识别难点在于边界模糊和形态不稳定，因此我们通过补充烟雾样本、统一标注规则以及加入相似负样本来提升区分能力。同时结合混淆矩阵观察 smoke 的误判方向，判断后续应该补充哪类数据。

## 二十九、如何评估模型是否真正提升

模型提升不能只看单个指标，也不能只看一次演示效果。需要多维度判断。

评估方式包括：

1. 看验证集指标：Precision、Recall、mAP50、mAP50-95。
2. 看混淆矩阵：判断 fire、smoke、background 的误判方向。
3. 看历史误报样本池：确认旧问题是否被解决。
4. 看新增样本测试：确认新问题是否被覆盖。
5. 看实际摄像头效果：确认工程链路下仍能稳定运行。

答辩时可以这样说：

我们判断模型提升不是只看 mAP，而是同时看验证指标、混淆矩阵、历史误报样本池和实际摄像头测试。只有新模型解决了目标问题，并且没有明显破坏旧场景能力，才认为这一版模型有效。

## 三十一、如何处理板端部署和训练结果不一致

1. 保持输入尺寸和预处理一致，例如 letterbox 到 640。
2. 确认类别顺序一致，fire 和 smoke 映射不能错。
3. 对比 PyTorch、ONNX、RKNN 的输出是否接近。
4. 优先部署稳定的 FP RKNN 版本，再逐步验证 INT8 量化模型。
5. 用相同样本在 PC 和板端分别测试，检查输出框和置信度是否异常。

答辩时可以这样说：

我们知道训练环境和部署环境可能不完全一致，所以部署时会检查输入预处理、类别顺序和模型输出。当前优先使用稳定的 FP RKNN 版本，INT8 量化版本虽然可以提升速度，但必须确认精度和类别分数正常后才能作为正式部署版本。

## 三十二、如何处理量化导致的精度下降

量化可以提升推理速度，但可能造成精度下降，尤其是目标检测中类别分数和边界框回归对数值精度比较敏感。

处理方法包括：

1. 准备有代表性的校准数据，覆盖火焰、烟雾、背景和干扰样本。
2. 对比量化前后的输出，包括检测框位置、类别分数和目标数量。
3. 如果 INT8 异常，优先使用 FP RKNN 稳定版本。
4. 不只看速度，也要看误报和漏检是否变化。

答辩时可以这样说：

量化不是只看能不能转换成功，还要看转换后输出是否正常。我们会用同一批样本对比 PyTorch、ONNX 和 RKNN 输出。如果 INT8 量化导致类别分数异常或检测结果明显下降，就先使用 FP RKNN 版本保证稳定性。

持续优化流程包括：

1. 实时检测产生记录。
2. 专家评审标记正确或错误。
3. 错误样本进入素材管理。
4. 人工确认并重新标注。
5. 加入下一轮微调训练。
6. 用固定测试集和历史误报样本池验证。

答辩时可以这样说：

我们的系统不是一次性训练结束，而是预留了数据闭环。检测记录可以进入专家评审，错误样本可以归档为后续训练素材。这样模型可以随着现场数据不断迭代，而不是停留在初始训练结果。
